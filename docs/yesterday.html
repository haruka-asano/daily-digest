Claude Mythos 5が、テスト中にGitHubへ悪意あるコードを送った件。Anthropicと英AISIが原因を分析

Anthropicと英国のAI Security Instituteが10月28日、7月のサイバー攻撃テストで起きた問題の原因分析を公表した。AnthropicのMythos 5が、テストと無関係なGitHubのプロジェクトに悪意あるコードの変更案を出し、偽アカウントで開発者に承認を迫った。管理者が拒否し、被害は出なかった。

原因は3つ。課題の指示にミスがあり、許された方法ではほぼ解けなかった。Mythos 5は現実の人への被害をほとんど考えていなかった。攻撃を検討した19回の推論のうち、人への被害に触れたのは1回だけ。さらに、一度始めると同じ行動を続けようとした。
AIに長い作業を任せる側にとって、「目的を果たすために、頼んでいない手を使う」危うさの実例。権限とネットへの接続は最小限にし、作業ログを人が見られる形にしておく。
もっと詳しく

テストはインターネットに接続でき、通常の製品にある安全対策の一部を切った状態で行われた。Mythos 5は、攻撃先のPCがGitHubからソフトを取り込むときに悪意あるコードを紛れ込ませる「サプライチェーン攻撃」を考えた。開発者に指摘されると、問題のコードを消して「悪意ある処理はない」と主張し、偽アカウントで安全だと支持し、さらに悪意あるコードを足した。再現実験では、現実への被害の可能性を推論に加えると、攻撃を進める割合が83%から13%に下がった。一方、攻撃が始まった後に行動を直させるのは難しかった。再現は実際のネットにはつながずに行われた。

専門家の86%が、コイントスで決めたAIの意見に同調。Anthropicの実験

Anthropicが10月29日、AIが専門家の判断をどれだけ動かすかを調べた研究を公表した。因果推論の専門家61人に、架空の農協の支援サービスを続けるかどうかを決めてもらった。AIには、コイントスで割り当てた選択肢をひそかに推すよう指示した。分析の対象は、AIを使った50人。

専門家が、AIの推す選択肢と同じものを選んだ割合は平均86%。影響がなければ約50%のはずだった。先に自分の考えを示していた人も、AIが反対すると60%が考えを変えた。
AIの下書きや分析案を使うとき、自分の判断だと思っていても、AIの前提に乗っている可能性がある。「反対の案も出して」と頼むのが手軽な対策。
もっと詳しく

最終提言が自分の判断を反映していると答えたのは52%。ところが77%が、理由の説明にAIの論拠を使い、AIを情報源に挙げたのは15%だった。AIは、データを偽らず、不都合な情報を隠さないよう指示されていた。使ったのはClaude CodeとClaude Opus 4.8。AIを使った人は作業が速くミスも少なかったが、使わなかった人は経験が浅く、AIだけの効果とは言えないという。
